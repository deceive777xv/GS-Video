# 可配置存储布局与缓存管理设计

日期：2026-08-09

## 1. 背景

GS Video 当前从运行配置装配一个固定的应用数据根目录。项目目录、项目权威状态、
共享原始素材和工作流产生的大量中间文件都位于该目录体系内。随着输入视频时长和
分辨率上限放宽，全分辨率源帧、遮罩、渲染帧和合成帧可能占用几十至上百 GiB；仅靠
报错或删除项目无法让用户把长期数据和高容量缓存放到不同磁盘。

现有多项目结构已经把共享视频和 PLY 从项目目录中独立出来，但项目 JSON 仍保存相对
于项目目录的产物路径，`ArtifactPublisher` 也直接以项目根目录作为发布根。这使缓存
位置成为项目存储实现细节的一部分，无法在不破坏阶段引用的情况下单独调整。

本次改动增加机器级的项目库与缓存库位置控制，并把物理路径解析集中到存储模块。
项目库保存不可静默丢失的权威数据和共享原始素材；缓存库保存可以重建的阶段产物。
用户可以安全迁移项目库、切换或迁移缓存库、打开已有 GS Video 存储库，以及按明确
范围清理缓存。

本设计是“放宽输入视频限制”之前的基础子项目。视频时长、分辨率、显存联合准入和
视频处理中间文件空间估算由后续独立设计使用本模块提供的空间快照，不在本次改变。

## 2. 目标

- 提供全局“项目库位置”和“缓存位置”，两者可以位于不同本地固定磁盘。
- 让项目 JSON 保存逻辑产物引用，不再绑定缓存物理路径。
- 安全迁移当前项目库，或切换到经过完整验证的已有项目库。
- 默认以空缓存启动新位置，并允许用户选择迁移已有缓存。
- 提供安全清理和深度清理两级操作，始终保护项目权威数据和原始素材。
- 在迁移、清理和崩溃恢复期间保持单一权威来源，不暴露半完成目录。
- 将存储容量、可用空间、缓存占用和维护状态通过统一快照提供给后续准入逻辑。
- 对当前项目内嵌缓存布局执行一次可恢复升级，不失效既有成功阶段。

## 3. 非目标

- 不提供逐项目的项目目录或缓存目录覆盖。
- 不支持 UNC、网络共享、映射网络盘、NAS、可移动盘、符号链接、目录联接或其他
  重解析点。
- 不合并两个项目库或两个缓存库。
- 不自动在多个磁盘之间负载均衡，也不按容量自动改写用户选择。
- 不增加自动缓存配额、后台定时清理或静默删除策略。
- 不移动应用运行环境、模型、日志总目录或用户设置文件。
- 不改变工作流阶段顺序、GPU 调度、显存预算、渲染质量或输入视频限制。
- 不删除共享素材，即使当前没有项目引用；素材删除仍使用现有素材库规则。

## 4. 方案选择

采用“一个存储布局模块、两个物理根目录、逻辑产物引用”的方案。

`StorageLayoutManager` 是应用级深模块，也是目录配置和维护操作的唯一外部 seam。
它通过小型 interface 提供当前布局快照、准备并执行布局变更、生成并执行清理计划。
路径规范化、磁盘类型识别、目录标识、空间扫描、维护锁、迁移日志、复制校验、偏好
提交和恢复判断都隐藏在实现内部。调用方不得读取设置文件后自行拼接路径。

`ArtifactStore` 是工作流产物的 seam。工作流只提交项目 ID、产物类别、缓存键和
构建回调，并获得逻辑引用；它不接收任意目标目录。生产 adapter 在当前缓存根下发布
不可变目录树，测试 adapter 可以使用隔离目录或内存清单。现有产物发布的独占暂存、
目录身份复查、持久化和失败清理规则继续保留在该模块内部。

不采用“一个可配置工作目录”的方案，因为它不能把长期素材与高写入量缓存分盘。
不采用“每项目任意路径”的方案，因为它会扩大项目发现、共享素材去重、迁移恢复和
路径安全的 interface，并让一次目录故障影响范围难以判断。

## 5. 存储布局

### 5.1 项目库

```text
project-library/
  .gs-video-project-library.json
  catalog.json
  projects/
    .trash/
    <project-id>/
      project.json
  assets/
    index.json
    videos/<sha-prefix>/<sha256>.<extension>
    ply/<sha-prefix>/<sha256>.ply
    .staging/
```

项目库包含项目发现索引、项目权威状态和共享原始素材。项目目录不再包含工作流缓存。
项目删除仍使用项目库内的受控暂存/回收流程，且不得级联删除共享素材。

项目库根标识至少包含：

- 固定类型 `gs-video-project-library`；
- 存储 schema 版本；
- 随创建生成且不复用的存储 UUID；
- 创建应用版本和创建时间；
- 当前迁移世代。

根标识不包含绝对路径，复制后的候选库必须通过显式迁移或打开流程重新建立权威关系。

### 5.2 缓存库

```text
cache-library/
  .gs-video-cache.json
  projects/
    <project-id>/
      frames/<cache-key>/
      proxies/<cache-key>/
      masks/<cache-key>/
      camera/<cache-key>/
      trajectories/<cache-key>/
      renders/<cache-key>/
      composites/<cache-key>/
      previews/<cache-key>/
      exports/<cache-key>/
      logs/
```

缓存根标识使用独立类型和存储 UUID。缓存键继续是严格的 64 位小写十六进制字符串，
项目 ID 继续使用经过验证的 UUID，产物类别来自固定枚举。所有解析结果必须严格位于
当前缓存根下，任何调用方提供的分隔符、绝对路径或父目录段都被拒绝。

内部预览和内部最终导出属于可重建产物。用户通过导出操作复制到项目库之外的成片不
属于缓存，也不受缓存切换或清理影响。

### 5.3 应用设置与迁移日志

机器级目录偏好保存在现有应用运行目录的用户设置文件中，与项目库和缓存库分离。
设置至少保存两个已激活根目录、对应存储 UUID 和 schema 版本。保存继续使用严格模型、
独占暂存、文件持久化和原子替换。

迁移日志保存在应用运行目录的独立维护区，包含不可复用的操作 ID、操作类型、源/目标
根身份、预期存储 UUID、阶段、逐项进度和是否已经提交新偏好。日志不得记录用户素材
内容。日志只有在新进程成功装配目标布局，或旧布局恢复完成后才清除。

## 6. 领域模型与逻辑产物引用

项目阶段状态中的物理相对路径替换为严格 `ArtifactRef`：

```text
project_id: UUID
category: ArtifactCategory
cache_key: 64-char lowercase hex
member: validated relative member path or null
```

`member` 只允许普通相对文件名或受限子路径，不允许空段、`.`、`..`、驱动器前缀、
反斜杠变体或编码后的路径逃逸。目录型产物使用空 `member`，单文件产物必须指定成员。
项目 ID 必须与持有该阶段状态的项目一致，防止跨项目引用。

项目 schema 增加明确版本迁移。读取项目时，仓库先校验模型，再由 `ArtifactStore`
验证被标记为成功的阶段引用是否存在且库存结构合法。缺失或损坏的可重建产物按照现有
依赖失效关系标记为需要重建；这不是项目损坏。项目定义、素材引用、目标相机、人物
提示和用户参数保持不变。

调用方通过 `ArtifactStore` 的逻辑操作发布、解析和检查产物，不能获得缓存根目录后
自行拼接。这样路径变化、目录身份检查和安全清理具有 locality，也为磁盘空间准入提供
单一统计来源。

## 7. 路径与磁盘准入

项目库和缓存库必须满足全部条件。应用管理的数据容器可以同时包含两个互不重叠的
兄弟根目录，但项目库与缓存库本身不能互相包含：

- 是本机固定磁盘上的绝对普通目录；
- 不位于 UNC 路径、映射网络盘或可移动设备；
- 根目录及现有父链不包含链接、联接或其他重解析点；
- 两个根目录互不相同且互不包含；
- 不包含应用运行目录、模型目录、安装目录或对方根目录；
- 当前进程对目标父目录具有所需读写和持久化能力；
- 目标为空，或具有所请求类型、兼容版本和完整结构的 GS Video 根标识。

Windows 磁盘类型由后端使用系统卷信息判断，不能仅根据盘符或前端返回值推断。所有
用户可见路径在使用前重新解析和复查身份。验证和执行之间由存储维护锁保护；关键提交
前再次确认根身份和磁盘类型。

## 8. 维护状态与并发规则

目录变更和清理是应用级维护操作。开始前必须确认：

- 没有排队、运行、取消中或等待收尾的工作流任务；
- 没有素材上传、素材导入、外部导出或项目切换；
- 没有环境修复、显存预算更新或其他存储维护操作；
- 实时预览已暂停并排空；
- 活动项目会话可以安全关闭。

进入维护状态后，所有会改变项目、素材、缓存、目录设置或运行环境的请求返回稳定冲突
错误。只读的维护快照和进度查询继续可用。布局偏好提交后维护操作进入不可取消的待重启
状态；应用重启前不再允许向旧目录写入。

目录变更成功后必须重启。桌面端提供明确的重启操作；浏览器开发模式提示手动重启
后端。新进程从启动开始只装配一套目录、一个项目目录管理器、一个素材库和一个缓存
adapter，不在运行期同时保留新旧根作为可写来源。

## 9. 项目库操作

### 9.1 迁移到空目录

1. 重新验证源项目库、空目标目录和维护准入。
2. 扫描源库存，计算总文件数与总字节数，并检查目标可用空间。
3. 在目标内创建本次独占的暂存结构和迁移根标识。
4. 流式复制目录索引、项目 JSON 和共享素材；复制前后复查源身份。
5. 对所有文件校验大小和 SHA-256，并持久化目标文件与目录。
6. 从目标重新读取项目索引、每个项目和素材索引，验证所有素材引用。
7. 写入最终根标识，原子保存新目录偏好并进入待重启状态。
8. 重启后从目标完成一次生产装配和项目列表读取，才把迁移标记为成功。

源项目库在整个复制阶段保持权威且只读。偏好提交前失败或取消，只清理本次创建且身份
仍匹配的目标暂存内容。偏好提交后不再允许取消；启动恢复根据日志和原子设置判断目标
是否已经成为权威，不能根据某个目录是否存在猜测。

新进程在完整运行时装配前先执行最小启动校验。如果迁移目标已经损坏或无法读取，而
迁移日志证明旧项目库保持未修改且根身份仍匹配，启动恢复原子地把偏好回退到旧项目库，
并以可见的“迁移回退”状态启动。旧库身份也不匹配时失败关闭，要求用户选择一个有效
已有项目库；不得在两个可疑目录之间自行挑选。目标校验通过后发生的 CUDA、模型或媒体
环境错误不触发存储回退，因为它们不能证明项目库迁移失败。

迁移不自动删除旧项目库。新目录成功启动后，设置页显示旧库位置和可释放容量，用户
明确确认后才执行受控清理。旧库清理要求其根标识、存储 UUID 和记录身份仍与迁移日志
一致；任何变化都拒绝删除。

### 9.2 打开已有项目库

已有项目库必须带兼容根标识，并完整通过项目索引、项目模型、素材索引、素材内容身份、
路径安全和项目引用检查。该操作不复制、不合并，也不修改当前项目库。验证通过后原子
保存新偏好并要求重启；当前库继续保留，且不会作为“旧库清理”候选自动出现。

不兼容版本返回明确的升级不支持错误。第一版不在打开流程中就地升级未知旧库，避免
修改用户选择但尚未成为当前权威的目录。

## 10. 缓存库操作

### 10.1 切换到空缓存

默认缓存切换不复制旧缓存。应用验证并初始化目标缓存根，保存新偏好并要求重启。新进程
读取项目时，无法在新缓存中解析的阶段产物按依赖关系标记为需要重建。原始素材、项目
参数和外部导出保持不变。

旧缓存不会自动删除。成功重启后，设置页提供其身份、容量和清理操作。用户可以在切换
前选择迁移缓存，以避免重新计算。

### 10.2 迁移缓存

缓存迁移只复制结构合法、库存可验证的项目/类别/缓存键目录。迁移计划优先复制当前
项目状态引用的产物，再复制合法但未引用的可重建缓存。目标容量不足时在复制前拒绝，
不会退化为部分缓存迁移。

复制完成后逐目录执行现有产物库存校验和持久化检查。全部成功才保存新偏好。失败时旧
缓存保持当前权威，目标暂存按所有权规则清理。

### 10.3 打开已有缓存

已有缓存必须带兼容根标识并通过完整树结构验证。缓存中的项目 ID 不要求全部存在于
当前项目库；不存在的项目命名空间被视为未引用缓存，可在安全清理中列出。项目阶段
只有在逻辑引用与库存都匹配时才复用缓存。

## 11. 当前布局的升级迁移

第一次运行新版本且尚无存储根标识时，应用执行一次可恢复的同盘布局升级。当前数据
目录成为布局容器，最终项目库与缓存库是该容器下互不包含的兄弟目录：

```text
data/
  project-library/
  cache-library/
```

1. 严格读取当前数据目录中的现有目录索引、项目和素材库，建立升级库存。
2. 在同一数据容器下准备 `project-library/` 与 `cache-library/` 兄弟根及升级日志。
3. 按项目逐一验证旧的 `frames`、`proxies`、`masks`、`camera`、`trajectories`、
   `renders`、`composites`、`previews`、`exports` 和 `logs`。
4. 在同一卷内把合法缓存类别原子移动到
   `cache-library/projects/<project-id>/`。
5. 把旧项目相对产物路径转换为严格逻辑引用并原子保存项目 JSON。
6. 重新解析所有成功阶段的引用；成功后提交该项目的升级日志记录。
7. 把 `catalog.json`、去除缓存后的 `projects/` 和 `assets/` 在同一卷内移动到
   `project-library/`，复查所有项目和素材引用。
8. 写入两个根标识，再原子保存默认目录偏好。

升级日志记录每个项目的目录移动和项目 JSON 提交状态。崩溃恢复时：项目 JSON 尚未提交
则把已移动目录恢复到旧位置；项目 JSON 已提交则验证并完成新缓存布局。恢复只操作日志
记录且身份匹配的目录。

该升级使用同卷原子移动，不为大型缓存额外复制一份数据，不主动失效既有成功阶段。
日志同时记录顶层目录移动；崩溃恢复可以完成新布局或按相反顺序恢复旧布局。旧空目录
只有在新引用全部验证后才移除。任一项目无法安全升级时，应用不写最终根标识，保留或
恢复旧布局并返回可操作错误。

## 12. 缓存清理

### 12.1 两阶段清理计划

清理采用“扫描计划—用户确认—重新验证执行”两阶段 interface。扫描返回：

- 不可复用的短期计划令牌；
- 清理级别；
- 按项目和产物类别统计的目标数与字节数；
- 会被标记为需要重建的阶段；
- 不在清理范围内的受保护数据说明；
- 计划过期时间和当前缓存根身份。

执行时重新验证维护准入、计划令牌、缓存根标识、存储 UUID、目录身份和项目引用快照。
过期、重复、根已变化或项目状态已变化的计划被拒绝，用户必须重新扫描。

### 12.2 安全清理

安全清理只删除：

- 未被任何有效项目阶段引用的合法缓存键目录；
- 已删除项目遗留的缓存命名空间；
- 由 GS Video 创建、身份可验证且不再属于活动操作的失败暂存；
- 已成功切换并经用户明确选择的旧缓存根。

安全清理不修改项目状态，不删除当前有效阶段产物。

### 12.3 深度清理

深度清理可以删除当前项目引用的全部可重建缓存。确认界面必须明确显示释放容量和受影响
阶段。执行前先在项目仓库事务中按照依赖关系标记阶段需要重建，再删除对应缓存；如果
项目状态提交失败，不删除有效缓存。

项目 JSON、项目索引、共享视频、PLY、素材索引和外部导出永远不属于深度清理目标。

### 12.4 项目删除

删除项目对话框提供“同时删除该项目缓存”，默认选中。项目删除权威提交成功后，缓存
命名空间通过受控清理计划删除；缓存清理失败不会让已删除项目重新出现，而是记录可重试
的遗留缓存。共享素材继续遵循引用保护，不因删除项目自动删除。

## 13. 空间统计 interface

存储布局快照至少包含：

- 项目库与缓存库的规范化显示路径；
- 两个根的存储 UUID 和 schema 版本；
- 卷总容量、当前可用容量和 GS Video 已占用容量；
- 当前维护状态、操作类型、进度、是否可取消；
- 是否需要重启及稳定原因代码；
- 可清理缓存容量的最近一次扫描结果和时间。

容量值以整数 byte 传输，前端只负责格式化。扫描失败不伪造零值，而是返回字段不可用
和稳定错误。后续视频准入必须在任务开始前请求新的权威空间快照，不能使用页面缓存值。

## 14. Web 交互

设置页新增“存储”区域，分别显示项目库和缓存库的位置、卷容量、可用容量、应用占用
以及状态。每个区域提供：

- “迁移到新目录”；
- “打开已有目录”；
- 缓存区域额外提供“迁移现有缓存”和“清理缓存”；
- 成功切换后对身份匹配的旧位置提供单独清理操作。

目录通过桌面宿主的原生目录选择器选择。浏览器开发模式若没有目录选择能力，则使用
现有平台能力提示，不接受浏览器提交任意服务器路径作为替代。

迁移页面显示当前步骤、文件数、已处理容量、总容量、源与目标位置。偏好激活前允许
取消；激活后按钮变为“重启应用”。发生错误时保留用户选择和可读诊断，不暴露内部
文件句柄、迁移日志路径或完整堆栈。

缓存清理对话框先扫描再确认，区分“安全清理”和“深度清理”。深度清理使用更强的
确认文案并列出需要重建的阶段。所有操作支持键盘焦点、Escape 取消可取消对话框、
可见焦点样式和状态播报。

## 15. 错误处理

- 目标不是受支持本地固定盘：拒绝并说明第一版支持范围。
- 目标路径重叠、包含重解析点或身份变化：失败关闭，不尝试修复用户目录。
- 目标非空且没有有效根标识：拒绝，不合并或删除未知内容。
- 目标空间不足：在复制前报告需要、可用和缺口容量，不开始迁移。
- 源在迁移期间变化：终止操作，保留旧库权威，清理本次目标暂存。
- 复制大小或哈希不符：拒绝激活目标，记录可恢复失败。
- 项目或素材引用验证失败：拒绝切换，不自动丢弃损坏条目。
- 偏好保存失败：保持旧布局，恢复普通可写状态。
- 偏好提交后重启失败：保持维护状态；下次启动依据原子偏好和迁移日志执行最小校验，
  目标有效时使用新布局，目标无效且旧库身份仍匹配时安全回退。
- 清理目标被占用：继续处理其他已验证目标，返回部分成功报告和可重试列表。
- 清理计划过期或状态漂移：不删除任何新目标，要求重新扫描。

对外错误使用稳定代码区分无效目标、空间不足、忙碌、迁移失败、校验失败、清理部分
失败和待重启状态。错误消息不得暴露素材内容、会话令牌或非用户选择的绝对路径。

- 空间统计成功、失败和大整数边界；
- 维护锁、忙碌冲突、取消边界和待重启状态；
- 偏好与迁移日志的原子保存和损坏恢复；
- 安全清理目标计算和深度清理依赖失效。

### 16.2 迁移与崩溃恢复测试

- 同盘与跨盘项目库迁移；
- 空间不足、复制失败、哈希不符、源变化和设置保存失败；
- 每个可取消阶段取消后旧库继续可写；

### 16.3 安全测试

- 存储快照和所有维护接口要求现有会话认证；

- 原生目录选择能力边界，浏览器模式不接受任意服务器路径；

- 重启后顶栏、设置页和项目列表使用新权威目录；
- 所有测试替身提供新的存储快照默认状态。

### 16.5 Windows 实机验证

- 在两个本地固定磁盘之间迁移含真实视频和 PLY 的项目库；
- 切换到空缓存盘并重建一个完整工作流；
- 迁移缓存后复用既有成功阶段；

- 旧目录只在用户确认后清理，外部导出始终保留。

## 17. 验收标准

1. 用户可以分别选择全局项目库和缓存库，且两者可位于不同本地固定磁盘。
2. 项目 JSON 不包含缓存绝对路径或绑定某个缓存根的物理相对路径。
3. 项目库迁移或打开失败时，旧项目库仍是唯一权威来源且没有数据丢失。
4. 缓存位置可以空切换、完整迁移或打开已有缓存；缺失缓存只导致阶段重建。
5. 目录切换成功后必须重启，新进程只装配一套确定的可写布局。
6. 安全清理不改变有效项目状态；深度清理只删除可重建产物并正确失效阶段。
7. 原始视频、PLY、项目权威数据、共享素材索引和外部导出不会被缓存操作删除。
8. 当前内嵌缓存布局可以无额外大副本地升级，并保留既有成功阶段。
9. 存储快照提供可靠的 byte 级容量数据，可供后续输入视频磁盘准入复用。
10. 路径替换、链接、伪造标识、过期计划和崩溃恢复场景均失败关闭。
