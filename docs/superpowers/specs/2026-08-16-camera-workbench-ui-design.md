# 机位工作台 UI 与源透视证据交互设计

日期：2026-08-16

## 1. 背景

当前“机位”页面把源透视校准、GS 探索与局部地面、合成机位三个复杂任务纵向堆叠在同一页面。宽屏或全屏时工作区和控件继续放大，源校准依赖五个间接滑块，GS 探索按钮占据右侧检查器，并且新的 6DoF 视口仍使用 React `onWheel`，不能可靠隔离页面滚动。

本设计沿用已经确认的受约束合成相机模型，只重组机位工作流，并把源透视输入从“用户猜测 FOV”改为“系统根据可审计证据求解 FOV”。

## 2. 目标

- 把机位页拆成三个可直接导航的子页面：源透视、GS 与局部地面、合成机位。
- 所有人物、预览和机位视口统一使用 16:9 外框；非 16:9 媒体使用 `contain` 留黑边，不能拉伸源图。
- 默认窗口与全屏使用相同的工作台尺寸上限；全屏只增加外围留白。
- 把 GS 局部平移做成覆盖在画面左下角的游戏式方向键，同时保留完整数值输入。
- 视口滚轮只影响 GS 相机，不滚动外部页面。
- 让视口、右侧当前任务检查器和下方低频操作形成稳定层级。
- 移除源透视 FOV、地平线端点和竖直线端点滑块。
- 通过画面内正交线段、可信相机内参或低置信度系统初值产生只读 FOV。

## 3. 已选择的布局方向

采用视觉方案 A“聚焦式工作台”：

- 顶部是三个子页面的步骤导航和完成状态。
- 主区域左侧为 16:9 视口，右侧为与视口基本等高的当前任务检查器。
- 低频、解释性或内容较多的操作放到主区域下方。
- 工作台使用固定最大宽度，不因进入全屏而继续放大。

未采用的方案：

- “大画布 + 全部控制置底”会增加画面与参数之间的视线往返，并使页面变长。
- “沉浸画布 + 浮动抽屉”会遮挡 GS，且不利于校准状态与显式确认的可发现性。

## 4. 页面与导航

机位页增加三个子路由：

```text
#/projects/:projectId/workflow/camera/source
#/projects/:projectId/workflow/camera/scene
#/projects/:projectId/workflow/camera/synthesis
```

旧的 `/workflow/camera` 根据项目状态进入最早未完成的子页面。三个子页面允许自由切换，不把探索 GS 强制锁在源透视之后；合成子页面在缺少源透视或局部地面时显示明确前置条件并禁用求解。

子页面切换不得丢失尚未提交的本地草稿。`CameraPage` 持有共享工作区状态和跨面板 mutation lock，各子页面只读写自己负责的草稿：

- 源透视页拥有锚定帧、线段证据和脚底候选草稿。
- 场景页拥有探索相机和未确认三点草稿。
- 合成页拥有模式、方位角、人物比例和构图草稿。

项目、源资产、分割、GS 或 authority 变化时，仍按现有 fail-closed 规则清理不再属于当前上下文的草稿和异步响应。

## 5. 共享工作台与 16:9 视口

新增共享 `CameraWorkbenchShell` 和统一视口样式：

- 工作台宽度为 `min(100%, 1120px)`，在可容纳该宽度的默认窗口和全屏窗口中保持同一 CSS 尺寸。
- 主区域使用约 804px 的 16:9 视口、16px 间距和 300px 检查器。
- 字体、按钮、输入框和间距使用固定 `rem`/`px` 设计值，不使用随视口继续放大的 `vw` 尺寸。
- 全屏不切换特殊放大布局；只增加工作台两侧留白。
- 宽度不足时先把检查器移到视口下方，再把下方多列卡片改为单列。

人物页、预览页和三个机位子页面共享 16:9 外框。媒体内容使用 `object-fit: contain`；坐标映射继续基于实际图像内容区域，点击黑边必须被拒绝。所有画面内标记、线段和三点覆盖层都使用同一 letterbox 几何换算。

## 6. 子页面一：源透视

### 6.1 页面结构

主区域左侧显示 16:9 源锚定帧，右侧显示：

- 当前证据方法；
- 参照关系；
- 证据质量；
- 只读垂直 FOV、Roll、重力方向和主点假设；
- 证据降级说明；
- “确认源透视校准”。

主区域下方放置：

- 全片 Alpha 可见性扫描、时间段统计、代表帧和锚定帧选择；
- 可选脚底接触候选与显式确认。

“透视线段”和“脚底候选”是互斥工具模式，避免拖线时误创建脚底候选。

### 6.2 画面内线段交互

默认工具显示 A、B 两组参照，每组包含两条可独立拖动端点的线段。用户把同组两条线贴到现实中平行、图像中汇聚的边缘；A 与 B 表示现实中互相垂直的方向。

为消除重力轴歧义，右侧提供两个参照关系：

- “A 为竖直，B 为水平”：适合门框、立柱、墙角、桌沿等画面。
- “A/B 位于水平面”：适合地砖、桌面、天花板或其他可信水平面。

拖动时：

- 端点跟随指针实时更新；按住 Shift 进入精调。
- 选中端点可用方向键逐像素移动，并提供清晰焦点样式。
- 本地预览求解器即时更新消失点、地平线和只读 FOV。
- 接近退化、两组并非正交可解关系或焦距非有限时，以颜色和文字说明问题，不允许确认高置信度校准。

透视网格可以作为明显错误检查，但不要求用户通过网格判断相机高度、人物高度或绝对尺度。

### 6.3 FOV 证据分级

FOV 始终只读，用户不能输入或拖动：

1. `orthogonal_guides`：由两组正交方向求解，几何条件良好时为高置信度。
2. `calibrated_intrinsics`：只接受来源明确、不是固定先验的镜头元数据或相机求解内参。
3. `automatic_prior`：没有足够几何或可信内参时使用系统初值，标记为低置信度，但允许进入视觉预览。

当前 OpenCV 相机轨迹求解器使用“中心主点、方形像素、垂直 FOV 60°”固定先验，因此该结果只能归入 `automatic_prior`，不能标成视频已经求出了 FOV。未来若相机求解 artifact 提供可验证的自标定内参，再升级为 `calibrated_intrinsics`。

### 6.4 求解与持久化

正交消失点预览可在前端即时计算，但确认时后端必须用原始像素线段重新求解和验证，前端不得直接提交任意 FOV、地平线或重力向量。

`SourcePerspectiveCalibrationRequest` 改为证据联合类型：

```text
common
- expected_project_id
- expected_segment_cache_key
- anchor_frame_index
- image_width / image_height

orthogonal_guides
- reference_relation
- group_a: two pixel line segments
- group_b: two pixel line segments

calibrated_intrinsics
- expected_camera_solution_cache_key

automatic_prior
- prior_source
```

持久化校准在现有派生字段之外增加：

```text
- evidence_method
- reference_relation
- guide_groups
- evidence_confidence
- evidence_diagnostics
- camera_solution_cache_key (when applicable)
```

后台求解假设方形像素、零 skew 和中心主点。两组消失点必须满足正交约束并产生正、有限焦距；由参照关系确定重力轴和水平面地平线。证据退化时返回可操作错误，不覆盖已有权威校准。

## 7. 子页面二：GS 与局部地面

### 7.1 探索控制

右侧检查器保留完整精确输入：

- X、Y、Z；
- Yaw、Pitch、Roll；
- 探索 FOV；
- 重置相机、聚焦 P0、冻结当前视角。

位置和角度输入维护可编辑文本：Enter 或失焦提交，Escape 恢复，负号和小数中间态不会触发预览。画面拖拽、滚轮、Orbit、方向键和数字输入都更新同一份探索相机草稿，并双向同步。

### 7.2 游戏式方向键

视口左下角覆盖：

- 十字排列的前、后、左、右；
- 相邻的上、下双键。

移动始终沿相机局部坐标系。按下立即移动一步，持续按住在短延迟后重复，`pointerup`、`pointercancel`、失焦或组件卸载必须停止重复。按钮阻止事件传给视口拖拽。

进入冻结三点取样模式后隐藏方向键，避免遮挡左下区域和误移动冻结相机；退出取样或重新探索后恢复。

### 7.3 滚轮隔离

不使用 React `onWheel` 负责取消默认滚动。视口真实 DOM 节点注册：

```text
wheel listener with { passive: false }
```

监听器同步调用 `preventDefault()` 和 `stopPropagation()`，只更新局部前后移动或 dolly；组件卸载时移除同一监听器。视口同时设置 `overscroll-behavior: contain`。鼠标离开视口后，页面滚动保持正常。

### 7.4 下方低频区域

三点候选、显式确认、法线翻转、P0 Orbit 选项、冻结 authority、相机 revision 和拾取缓冲状态放到视口下方。继续保留现有规则：三点来自同一冻结相机和拾取缓冲；移动相机清理未确认候选；已确认局部地面保持独立 authority。

## 8. 子页面三：合成机位

左侧始终为 16:9 真实静态合成预览，右侧检查器包含：

- 纯透视／脚底接触模式；
- 场景方位角精确输入；
- 人物与场景比例滑杆和数值；
- 纯透视模式的构图横移、纵移；
- 更新受约束合成预览；
- 确认合成机位。

纯透视模式允许直接拖动画面中的人物调整构图，拖拽与横纵数值双向同步。该操作更新目标相机相对于 P0 的局部平面内平移，不能成为后处理像素平移，也不能改变 FOV、Pitch 或 Roll。

接触模式固定脚底到 P0 投影并禁用构图平移。相机 Yaw、Pitch、Roll 和垂直 FOV 始终作为派生只读结果显示，不提供直接编辑。

下方区域显示构图交互说明、源透视与局部地面 revision、草稿/确认状态和透视证据等级。低置信度系统初值允许预览，但必须始终显示“估计值”口径。

## 9. 状态、并发与失效

- 三个子页面继续共享单一 mutation lock，禁止跨面板并发写入。
- 每个异步成功和错误响应都必须校验项目、资产、revision、相机指纹和请求序号后才能发布。
- 源透视草稿变脏时，合成求解和确认保持禁用。
- 修改锚定帧、线段证据、参照关系或证据方法会失效源校准确认及下游合成机位。
- 修改探索相机只影响实时画面和未确认三点，不得直接成为合成机位。
- 修改局部地面、法线方向、合成模式、方位角、比例或构图平移继续按现有设计精确失效下游产物。
- 子页面路由变化不是 authority 变化，不应取消仍属于当前项目的已提交结果。

## 10. 错误与边界

- 源图没有两组可信正交方向时，不要求用户猜 FOV；自动降级为可信内参或低置信度系统初值。
- 强鱼眼、全景、明显非针孔投影继续显示不支持提示。
- 同组线段在图像中近似平行、线段太短、两消失点关系退化或计算得到非正焦距时拒绝确认。
- 低置信度初值只允许“视觉上可信、可预览微调”的输出，不宣传为可靠透视校准。
- 16:9 外框不能改变后端图像坐标；黑边、缩放和窗口变化后端点及点选仍映射到原始像素。
- 右侧操作超过视口高度时，低频区域移到下方，不在右侧形成长滚动柱。

## 11. 可访问性

- 三步导航使用 `nav`、当前页语义和清晰完成状态，支持键盘访问。
- 线段端点、方向键和所有画面内工具都有可读标签、焦点样式和键盘等价操作。
- 方向键点击目标不少于 40×40 CSS px，并在取点模式隐藏。
- 证据质量不能只用颜色表达；必须同时提供“高／中／低”和具体错误文字。
- 数字输入保留可编辑中间态并提供合法范围、单位和恢复行为。
- `prefers-reduced-motion` 下取消非必要过渡，不影响实时预览功能。

## 12. 验证

### 12.1 数学与后端

- 已知内参和两组正交消失线能恢复容差内 FOV、地平线和重力方向。
- 两种参照关系都能得到正确重力轴；轴符号稳定且画面向下方向一致。
- 近退化、非正交、非有限、越界和非正焦距证据 fail closed。
- 后端忽略前端派生读数，只从提交的原始证据重新求解。
- 固定 60° 的现有 OpenCV 内参被标为低置信度先验，不得标成已求解内参。
- 证据、camera solution cache key 和现有项目 authority 的失效规则有集成测试。

### 12.2 前端交互

- 三个子路由可直接访问、前进后退，并保留当前项目的未提交草稿。
- 所有视口外框为 16:9；非 16:9 媒体 letterbox 后坐标仍正确。
- 线段端点指针和键盘操作更新只读求解结果，退化状态禁用确认。
- X/Y/Z、Yaw/Pitch/Roll 和探索 FOV 精确输入与拖拽、方向键、滚轮双向同步。
- 按住方向键重复移动，取消、失焦和卸载后不会继续移动。
- 冻结取点模式隐藏方向键，不遮挡三点选择。
- 可取消 wheel 事件在 GS 视口内被取消且不会滚动页面；卸载后监听器清理。
- 纯透视构图拖拽不改变 FOV 或旋转；接触模式禁用拖拽。
- A→B→A 项目、锚定帧、相机与模式切换丢弃旧成功和旧错误。

### 12.3 真实窗口验证

使用真实桌面浏览器或应用窗口检查：

- 默认窗口、2560×1440 和 3840×2160 全屏下，工作台在有足够空间时保持同一 CSS 宽度，内部按钮、输入和视口边界尺寸不变。
- 1280×800 及更窄窗口按既定断点重排，无水平溢出和被底部工作流栏遮挡的内容。
- 人物、预览、源透视、GS 探索和合成机位五类视口都呈现 16:9 外框。
- 鼠标位于 GS 视口内滚轮只移动相机；移出视口后页面恢复滚动。
- 右侧检查器与视口视觉等高，低频操作位于下方，不形成超长右栏。

## 13. 完成标准

用户可以在三个独立但状态连续的机位子页面中完成工作；所有视口统一 16:9；全屏不放大内部工作台；GS 方向键覆盖在画面左下角且保留完整数值输入；滚轮不再带动页面；源 FOV 由可审计证据或明确的低置信度系统初值产生，而不是由用户估计。
