# 机位输入、视口滚轮与预览适配设计

日期：2026-08-01

## 背景与目标

机位页目前只能通过拖拽调整 Yaw/Pitch，缺少精确输入；Gaussian 视口使用 React `onWheel`，而 React 19 将 wheel 根监听器注册为 passive，导致合成事件中的 `preventDefault()` 无法可靠阻止页面滚动。预览页的图片和视频会按媒体固有高度撑开 grid 行，使内容越过当前页面可用高度。

本次只优化这三项交互，不改变相机 API、Gaussian 渲染算法、预览生成流程或页面视觉风格。

## 设计

### Yaw/Pitch 精确输入

机位控制区新增 Yaw 和 Pitch 数字输入框。输入框维护可编辑文本，避免输入负号或小数中间态时立即产生无效相机请求；按 Enter 或失焦时提交。

- Yaw 接受有限数值，并归一化到 `[-180°, 180°)`；输入 `180°` 规范化为 `-180°`。
- Pitch 接受有限数值，并限制到 `-89°～89°`。
- 提交成功后写入现有受控 camera 状态，沿用 150 ms 预览防抖。
- 拖拽改变相机后，输入框同步显示最新角度。
- Escape 放弃未提交内容并恢复当前相机值；无效文本恢复当前值，不触发预览。

### Gaussian 视口滚轮隔离

不再依赖 React 合成 `onWheel` 阻止滚动。`SceneViewport` 在真实视口 DOM 节点上注册原生 `wheel` 监听器，并显式使用 `{ passive: false }`。监听器同步调用 `preventDefault()`，随后更新距离；卸载时移除同一个监听器。

因此鼠标位于 Gaussian 区域时，滚轮只执行 dolly；鼠标离开该区域后，外部页面保持正常滚动。距离仍限制在 `0.1～100`，预览请求与旧响应失效规则保持不变。

### 预览媒体高度适配

预览卡片获得受当前窗口可用高度约束的明确高度，图片和视频作为绝对定位媒体层填充卡片的媒体行并使用 `object-fit: contain`。字幕栏继续占据卡片底部的独立 grid 行，不被媒体覆盖。

宽屏和窄屏分别使用与人物页一致的 `clamp()` 高度策略，避免横屏、竖屏或异常比例媒体通过固有尺寸撑高页面。视频控件和播放行为不变。

## 错误与边界

- Yaw/Pitch 的空字符串、非有限数值和无效中间态不会更新相机。
- Yaw 的 `180°` 与 `-180°` 都规范化为 `-180°`，避免输入框来回跳变。
- 原生 wheel 监听器只绑定当前 viewport 节点，并在 effect cleanup 中移除，避免 StrictMode 重挂载造成重复缩放。
- 预览媒体只调整显示尺寸，不改变后端输出分辨率或下载内容。

## 测试边界

自动化测试使用公开 UI：

- 输入 Yaw/Pitch 后按 Enter 或失焦，相机读数更新并触发符合范围的预览请求；拖拽后输入值同步。
- 对 Gaussian 视口分发可取消 wheel 事件，断言事件被取消且距离发生变化；卸载后监听器清理。
- 现有相机确认、落脚点和预览 authority 测试继续通过。

布局通过真实浏览器验证：在 1280×800 窗口加载纵向或超高比例的图片/视频，预览卡片、字幕和底部工作流栏均保留在可视页面内，页面不因媒体固有高度新增纵向溢出。

## 完成标准

用户可以精确提交 Yaw/Pitch；Gaussian 区域内滚轮不会移动外部页面；预览图片和视频都按可用高度完整包含。前端全量测试、类型检查、生产构建和真实浏览器布局检查通过。
