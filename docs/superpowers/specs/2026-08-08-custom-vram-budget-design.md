# 可自定义显存预算设计

日期：2026-08-08

## 1. 背景

应用当前以 8 GiB NVIDIA 显存作为基准，并在运行配置、环境诊断、Gaussian
场景准入、实时预览和正式渲染中使用固定的 8192 MiB 上限。Web 顶栏也只显示
固定的“8 GB 模式”。这会使显存更大的设备无法主动向应用开放更多资源，而且
环境报告会把检测到的显存截断到配置预算，无法同时表达物理总量和当前预算。

本次改动增加机器级显存模式设置。用户可以保留标准 8 GiB，也可以在软件允许的
1 GiB 下限与当前 GPU 的物理总显存之间自定义可用显存预算。设置在 GPU 工作空闲时
立即生效，并在应用重启和环境修复后保持。

## 2. 目标

- 将显存预算下限定义为 1024 MiB，上限定义为当前 GPU 的物理总显存。
- 保留 8 GiB 标准模式，并提供自定义预算与“全部显存”快捷选择。
- 让实时预览、场景准入、正式渲染和环境诊断共享同一份动态预算。
- 空闲时修改后立即生效；GPU 任务或环境修复运行时禁止修改。
- 将物理总显存与当前预算分别展示和传输。
- 机器级持久化用户选择，不把资源偏好写入项目权威状态。
- 降低预算时不删除现有项目数据、阶段结果或产物。

## 3. 非目标

- 不根据任务负载自动改变预算。
- 不允许任务执行中途热切换预算。
- 不改变现有的 GPU 串行准入策略、80% Gaussian 场景准入阈值或渲染质量。
- 不增加多 GPU 选择；本次仍使用当前 renderer worker 探测到的设备。
- 不把“全部显存”解释为当前空闲显存；它表示设备报告的物理总显存。

## 4. 方案选择

采用统一显存预算服务，而不是分别修改各 GPU 服务中的数值，也不要求用户重启。

新增 `VramBudgetManager` 作为运行期唯一预算源。环境诊断、`PreviewSession`、
`WorkerPreviewService` 和 `RendererWorkflowService` 不再各自持有固定的 8192 MiB
副本，而是在一次工作开始或准入判断发生时读取统一快照。这样一次修改不会造成
预览采用新预算、正式渲染仍采用旧预算的状态分裂。

## 5. 领域模型与持久化

### 5.1 预算快照

后端对外返回一份严格快照，至少包含：

- `minimum_vram_mb`：固定为 1024；
- `total_vram_mb`：renderer worker 探测到的物理总显存；
- `selected_vram_mb`：用户当前选择；
- `mode`：`standard` 或 `custom`；
- `editable`：当前是否允许修改；
- `blocked_reason`：不可修改时的稳定原因代码；
- `recovered_from_invalid_preference`：启动时是否从无效偏好恢复。

标准模式的目标值为 8192 MiB，但在物理总显存小于 8192 MiB 时使用物理总量。
任何有效预算都必须满足：

```text
1024 <= selected_vram_mb <= total_vram_mb
```

如果物理总显存小于 1024 MiB 或无法探测，设置不可编辑，现有环境诊断负责报告
CUDA 或 renderer 不可用；不得伪造一个可用上限。

### 5.2 偏好文件

用户偏好保存在 `.runtime/user-settings.json`，与自动生成的
`.runtime/desktop-runtime.json` 分离。偏好文件只包含显存模式和所选 MiB 数值，
使用严格字段校验、临时文件与原子替换写入。

桌面运行配置生成器读取该偏好并把有效预算带入启动配置。环境修复刷新运行配置时
也走同一路径，因此不会覆盖用户选择。

偏好文件缺失时使用标准模式。文件内容损坏、字段非法或保存值超过当前物理总显存
时，应用采用 `min(8192 MiB, total_vram_mb)` 的安全默认值并设置恢复提示，但不因
一个可恢复的用户偏好阻止应用启动。损坏文件不作为新项目状态写回。

## 6. API 与运行期数据流

新增受现有会话认证保护的显存预算查询和修改接口：

- 查询返回当前预算快照；
- 修改只接受显式模式和严格整数 MiB；
- 布尔值、浮点数、字符串数字、低于 1024 MiB 或超过物理总显存的请求均被拒绝；
- 返回修改后的权威快照，前端不自行推断最终值。

环境报告继续返回 `vram_limit_mb` 作为当前预算，并让 `vram_mb` 表示物理总显存，
不再使用 `min(free, total, configured)` 截断物理总量。需要当前空闲显存时由内部
GPU 准入逻辑独立处理，不复用物理总显存字段。

一次修改按以下顺序串行执行：

1. 重新探测当前 GPU 的物理总显存并校验请求；
2. 确认没有活动 GPU 阶段或环境修复；
3. 暂停并排空实时预览，关闭常驻 preview worker，释放旧预算下的 CUDA 状态；
4. 原子保存用户偏好；
5. 发布新的预算快照；
6. 恢复实时预览能力，后续请求按新预算重新创建 worker。

修改锁保证同时只有一个更新流程。保存前发生错误时保持旧预算；保存失败时不发布
新预算并恢复旧预算下的预览能力。发布后的内部恢复失败不回滚已持久化预算，而是
关闭预览会话并通过现有可重试资源错误报告；下一次预览可按新预算重新初始化。

## 7. 忙碌与一致性规则

以下状态禁止修改：

- 分割、渲染、合成或导出阶段正在运行；
- 环境修复正在运行或取消中；
- 另一个显存预算修改正在提交。

后端是忙碌判断的权威来源，冲突请求返回稳定错误码。前端根据已知任务状态提前禁用
编辑，但不能替代后端校验。普通相机拖动产生的实时预览不是长期锁定条件；更新流程
会暂停并排空它，因此空闲工作流中的用户可以直接修改预算。

各消费者读取预算的时机如下：

- 环境诊断每次检查时读取当前快照；
- 实时预览在创建或重建 worker 时读取当前快照；
- 场景预览在每次准入判断时读取当前快照；
- 正式渲染在阶段开始时固定一次预算快照，阶段内部保持不变。

由于任务运行期间禁止修改，正式渲染不需要处理中途预算漂移。

## 8. 降低预算的行为

显存预算是资源准入设置，不是项目内容。降低预算时：

- 不修改项目 JSON；
- 不撤销已成功阶段；
- 不删除预览、深度、合成或导出产物；
- 不自动降采样 Gaussian 场景；
- 后续预览或正式渲染若超过现有 80% 准入阈值，则使用现有资源错误类别拒绝，并在
  消息中同时给出场景估算值与当前预算；
- 用户调高预算后可以直接重试原操作。

## 9. Web 交互

顶栏固定的“8 GB 模式”改为显存预算按钮，例如“显存 12 GB”。点击后打开紧凑
设置面板，包含：

- 物理总显存、当前预算和允许范围；
- “标准 8 GB”快捷选项；
- “自定义”模式；
- 自定义滑块与 GiB 数值输入框；
- “全部显存”快捷操作；
- “取消”和“应用”操作；
- 行内状态与错误信息。

界面以 GiB 展示，常规步进为 0.25 GiB，即 256 MiB。数值提交前换算成严格整数
MiB。“全部显存”不按 0.25 GiB 取整，而是精确提交探测到的 `total_vram_mb`。
输入框必须允许用户编辑中间态，但只有合法完整值才能启用“应用”。

任务运行时仍可打开面板查看信息，但输入、快捷选项和应用按钮被禁用，并显示
“GPU 任务结束后可修改”。更新成功后，顶栏、设置面板和导入页预算立即使用服务端
返回值刷新。

面板支持键盘打开和关闭、合理的焦点进入与返回、Escape 取消、可见焦点样式、
关联标签以及错误状态播报。保存错误时保留用户输入和原权威预算，便于修正或重试。

## 10. 错误处理

- 预算越界：拒绝请求并返回当前上下限；
- GPU 探测失败：设置只读，不改变已保存偏好；
- 活动任务或环境修复：返回冲突错误，提示稍后重试；
- 偏好保存失败：保留旧预算并恢复旧预览能力；
- 预览排空失败：关闭预览会话，不发布或保存新预算；
- 新预算发布后的预览恢复失败：保留新预算，下一次请求重新初始化预览；
- 无效持久偏好：采用安全默认值并返回一次可见恢复提示。

错误响应不得暴露本地绝对路径、worker 命令或配置文件内容。

## 11. 验证策略

### 11.1 Python 单元测试

- 1 GiB 下界和物理总显存上界；
- 精确边界接受，越界、布尔值、浮点数和字符串数字拒绝；
- 标准 8 GiB 默认值与低显存设备的默认收缩；
- 偏好原子保存、重启恢复、损坏恢复和环境修复保留；
- 更新锁、活动任务冲突与环境修复冲突；
- 修改成功、保存失败、预览排空失败和恢复失败的状态一致性；
- 所有 GPU 消费者读取同一预算源；
- 删除各处固定 8192 MiB 上限后，worker 协议仍严格验证正整数。

### 11.2 API 集成测试

- 查询和修改接口要求认证；
- 返回物理总显存与当前预算的不同字段；
- 修改后 bootstrap、环境报告和后续预览反映新值；
- 忙碌状态返回稳定冲突错误；
- 降低预算后已有项目与产物保持不变，新的超预算工作被拒绝。

### 11.3 Web 测试

- 顶栏显示当前权威预算；
- 标准、自定义、0.25 GiB 步进和全部显存；
- 非 0.25 GiB 的物理总量可通过“全部显存”精确选择；
- 忙碌禁用、保存中状态、错误保留和成功刷新；
- 键盘、焦点和无障碍标签；
- 所有 BackendClient 测试替身提供新的预算 DTO 与方法。

### 11.4 完成门槛

- 相关 Python 单元与 API 集成测试通过；
- Web 测试与 TypeScript 类型检查通过；
- Ruff 与 Mypy 通过；
- Web 生产构建通过；
- 在真实桌面启动路径验证设置重启保持，并确认环境修复不会覆盖偏好。

## 12. 验收标准

1. 用户能在 1 GiB 到物理总显存之间设置预算，并可一键选择全部显存。
2. 空闲时设置立即生效，GPU 任务或环境修复期间无法修改。
3. 顶栏、导入页、环境报告、预览和正式渲染使用同一权威预算。
4. 应用重启和环境修复后保留用户选择。
5. 预算降低不删除或篡改任何项目数据与既有产物。
6. 超预算的新工作被安全拦截，并提供可操作的错误信息。
