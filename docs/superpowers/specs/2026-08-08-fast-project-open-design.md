# 项目快速打开设计

日期：2026-08-08

## 1. 背景

项目首页点击“继续制作”后，前端即使正在打开当前活动项目，也会在导航前同步执行一次
完整 bootstrap。真实本地 API 与 Edge 浏览器测量显示：项目激活约 4.5 ms，项目列表读取
约 9.6 ms，完整 bootstrap 每次约 3.95–4.05 s；点击到工作流路由出现约 3.97 s。

bootstrap 会执行环境检查并暂停、恢复实时预览。它适合应用连接、进入首页和环境修复后
恢复权威状态，但不是进入一个已经由项目响应确认的工作流页面所必需的数据依赖。

## 2. 目标

- 点击当前项目的“继续制作”后直接进入其可达工作流步骤，不发起项目激活请求。
- 点击其他项目时只等待项目激活，激活成功后立即进入其可达工作流步骤。
- 项目打开不再同步等待完整 bootstrap，真实浏览器打开时间低于 1 秒。
- 保持现有项目权威、任务冲突、路由恢复和错误提示语义。

## 3. 非目标

- 不改变 bootstrap 的环境检查内容、缓存策略或预览暂停规则。
- 不改变项目会话构造、项目目录、共享素材或工作流阶段逻辑。
- 不增加进度条、骨架屏或新的路由依赖。
- 不优化应用首次连接时的 bootstrap 等待。

## 4. 方案

采用“激活响应即为打开项目所需权威”的方案。`openProject` 只执行以下流程：

1. 如果目标就是当前活动项目，直接复用内存中的权威 `ProjectDto`；否则调用
   `activateProject(projectId)` 并等待返回目标项目。
2. 通过现有 `acceptProject` 接受返回项目并重置项目相关任务状态。
3. 根据项目权威计算当前可达工作流步骤。
4. 立即更新 hash 路由并呈现工作流。

打开链路不再调用 `refreshCatalog()`。项目卡片列表在点击前已经来自首页 bootstrap；进入
工作流后不消费该列表。用户再次返回首页时，现有首页 effect 会重新请求 bootstrap，更新
项目列表、环境状态和其他应用级摘要。

不采用导航前轻量刷新项目列表的方案，因为打开项目不依赖列表，额外请求没有用户价值。
不采用保留四秒等待并增加进度条的方案，因为等待来自非必要工作，可以直接消除。

## 5. 状态与并发

- 当前项目打开不访问后端，因此不会与环境检查或项目锁产生新的竞争。
- 其他项目仍以 `activateProject` 成功响应作为切换提交点；激活期间保持在首页。
- 激活响应返回后，`acceptProject` 先于路由更新执行，工作流 route effect 会识别目标项目
  已经是当前权威，不会再次激活。
- 首页已有的后台 bootstrap 在离开首页时由现有 `AbortController` 阻止提交过期结果；服务端
  请求可以自然结束，但不能覆盖前端当前项目状态。
- 任务运行时仍由现有按钮禁用和服务端 `project_task_active` 冲突共同保护。

## 6. 错误处理

- 目标项目激活失败：保持首页与原活动项目，继续使用现有错误横幅，不改变路由。
- 当前项目直接打开：没有新增失败点。
- 返回首页后的 bootstrap 失败：使用现有首页错误处理，不影响已经打开的项目权威。
- 不把后台刷新错误伪装为项目打开失败，也不在激活成功后把用户导航回首页。

## 7. 验证

### 7.1 Web 回归测试

- 当前项目点击“继续制作”时立即进入其可达步骤，并且不调用 `activateProject`。
- 其他项目在 `activateProject` 完成后进入返回项目的可达步骤，且只激活一次。
- 将 bootstrap mock 保持为未完成状态时，点击“继续制作”仍可进入工作流，证明打开链路
  不再依赖 bootstrap。
- 项目激活失败时仍停留首页并显示错误。

### 7.2 真实链路验证

- 使用本地 API 与 Microsoft Edge，从项目首页点击“继续制作”，测量点击到项目工作流
  hash 路由出现的时间。
- 验收预算为低于 1000 ms；保留改动前约 3972 ms 的测量作为对照。
- 确认工作流首屏、当前项目名称和可达步骤正确，浏览器控制台没有新增错误。

### 7.3 完成门槛

- 相关 Home/App Web 测试通过。
- 全量 Web 测试、TypeScript 检查和 Web 生产构建通过。
- 真实 Edge 浏览器项目打开时间低于 1 秒。

## 8. 验收标准

1. 点击当前项目“继续制作”后无需等待环境检查即可进入工作流。
2. 点击其他项目只等待真实项目激活，不执行第二次同步 bootstrap。
3. 项目打开失败仍停留在首页，原活动项目和错误提示保持正确。
4. 返回首页后项目列表和应用级状态仍由现有 bootstrap 正常刷新。
5. 真实浏览器点击到工作流路由出现的时间低于 1 秒。
